# 寻龙工作台

一个可解释、可回测、可校准的 A 股研究系统。它复刻了你提供材料中的核心工作流，但不冒充原产品，也不声称还原了未公开源码或隐藏参数。

## 已实现

- 原“隔夜候选池”已改为手动自选研究池：用户添加沪深主板股票后，逐只生成新闻面、技术面和财报面分析；不会自动选股或对外推票
- “超跌反弹”已升级为资金启动版 P0/R0 模式：只从同花顺当日强势人气池选股，默认要求成交额至少1亿元、成交额达到近5日均值1.5倍、阳线上涨且大单净量为正，再识别已知低点 P0、左侧第2根K线压力 R0、约2倍量突破与均线确认；二波严格要求3–9日缩量回踩后再放量突破一波高点
- 新增独立 `擒龙模式`：量化沪深主板初筛后，依次判断情绪周期、主线板块、板块强度、龙头地位、抗跌/超预期和弱转强/首次分歧/回流买点；冰点、退潮、中位负反馈或数据缺失时禁止推送
- 所有策略选股统一使用沪深主板（`000/001/002/003/600/601/603/605`）；创业板、科创板、北交所、ST、退市整理、停牌、严重缺失和流动性不足均不入选
- 主板股票池先做快照评分，再对排名靠前的标的做 K 线/量价确认；扫描上限是确认预算，不是股票池上限
- “选好票”默认执行擒龙模式；不使用隔夜选股池，交易日09:20-09:29以当日实时快照和竞价重建候选，09:28仅推送通过方向、数据新鲜度与风险闸门者，最终最多输出3只
- 规则库输出风险旗标、数据覆盖率、市场情绪、触发条件、仓位上限和退出计划；经验阈值标注为“待回测”
- 事件模式保留 14 项可审计闸门，作为触发确认层，不再替代收益逻辑
- 个股实时行情、规则库综合评分、技术确认指标、价位触发条件
- 30 日主力阶段拆解（吸筹、洗盘、反转、主升、派发等量化标签）
- 15:01 复盘、历史回测、命中率及 7 日最佳涨幅统计
- 09:26 预扫描、09:28 微信推送、15:01 收盘复盘和每周六本地任务
- 企业微信群机器人 Webhook 配置、测试推送与定时任务自动投递
- 机器人指令模拟：`选好票`、六位代码、`深度分析 代码`、`复盘`、`状态`、`/sethome`
- SQLite 审计：数据快照、评分拆解、闸门结果、策略版本和最终决策
- 集合竞价采用分层取数：09:25 终态优先 FFD `ffd_market_microstructure(task="call_auction")`；09:15–09:25 盘中优先腾讯虚拟撮合价；两者不可用时才使用东方财富公开快照。每条结果保留来源、交易日、时间和有效状态，旧日期快照不会冒充当日竞价。

## 数据架构

```text
浏览器工作台
    ↓ 统一 JSON API
FastAPI 服务
    ├─ FFD 全市场增强日线：股票池、行情、量比、换手率、流通市值与均线
    ├─ FFD 批量行情：个股/指数实时快照、批量历史 K 线与市场宽度
    ├─ FFD 专项数据：09:25 竞价终态、涨停池、新闻、公告和财务指标
    ├─ 本地通达信：仅在 FFD 精确交易日资产不可用时兼容降级
    ├─ 腾讯/新浪/东方财富/巨潮：仅作为对应 FFD 请求失败后的显式兼容回退
    └─ AStockLab 本地 CSV：已有预测与本地研究缓存（可选）
        ↓
    TTL 缓存 + 提供者限流 + SQLite 审计
```

全市场扫描、个股/指数行情、候选 K 线、新闻、公告和财务面统一以 FFD 为主源。历史 K 线对候选池执行一次批量请求，不会拆成逐股调用；只有 FFD 精确日期或字段不可用时才启用带来源标记的兼容回退。页面顶部显示行情源时间而非请求时间，并在行情日期、候选池日期不一致时明确提示。

全市场实时快照不可用时，系统可读取 `XUNLONG_UNIVERSE_FILE` 指向的 HTML 代码目录作为降级覆盖（仍明确标记数据降级，价格/财务因子必须重新核验），并继续执行科创板和风险排除。未配置该变量时不启用此回退。

## 快速开始

```bash
git clone https://github.com/Hu-ge1/xunlong-workbench.git
cd xunlong-workbench
pip install -r requirements.txt
python server.py
```

浏览器打开：<http://127.0.0.1:8765>

Windows 下也可以双击仓库根目录的 `启动寻龙工作台.cmd`：它会先在后台拉起服务，用 `/api/health` 核验应用身份，再用 Edge 应用模式打开工作台。

```powershell
# 等同于上面的双击启动
.\launch_desktop.ps1
```

启动脚本接受两个环境变量：

- `XUNLONG_WORKBENCH_DIR` —— 项目目录，默认就是脚本所在目录
- `XUNLONG_PYTHON` —— Python 解释器路径，默认自动发现

隐藏启动日志写入 `data/server.current.out.log` 与 `data/server.current.err.log`。

健康状态分为“正常、降级、异常”。“降级”表示工作台仍可用，但部分主数据源不可用并已启用明确标记的后备来源；例如 FFD 日线未就绪时回退到本地通达信。

## 配置

复制 `.env.example` 为 `.env` 后按需填写。所有变量都是可选的，未配置时工作台仍能启动，只是对应的本地数据源会被标记为“未配置/降级”。常用的几个：

| 变量 | 用途 |
| --- | --- |
| `XUNLONG_QMT_PATH` / `XUNLONG_QMT_DIRS` | 本地 QMT 客户端与 xtquant 库位置（留空则按盘符通配 `*QMT*` 自动探测） |
| `GUPIAO_TDX_VIPDOC` | 本地通达信日线目录 |
| `OBSIDIAN_VAULT_PATH` | Obsidian 库根目录，复盘报告与策略规则读写都基于它 |
| `ASTOCKLAB_ROOT` | 可选的 AStockLab 本地缓存 |
| `XUNLONG_UNIVERSE_FILE` | 可选的离线代码目录（HTML），仅作降级覆盖 |
| `XUNLONG_DATA_DIR` | 迁移 SQLite 数据库与缓存目录 |

## 首次使用

1. 打开“自选研究池”，可以单只输入代码，也可以从表格、微信或网页复制股票列表后粘贴批量导入；系统自动提取6位代码、去重并过滤非沪深主板。
2. 单只添加会立即生成新闻面、技术面和财报面分析；批量导入可以选择立即分析，也可以稍后单只刷新或“分析全部”。
3. 原系统样本可以继续作为历史校准集；策略版本变化后应重新跑样本内外回测。

## 口径说明

- 红色表示上涨、绿色表示下跌，符合 A 股界面习惯。
- 回测总涨跌：`(当日收盘 - 当日开盘) / 当日开盘 × 100%`。
- 命中仅统计实际推送记录；校准样例不会伪装为实时业绩。
- 7 日最佳以推荐日开盘为基准，取随后最多 7 个交易日最高价。
- 历史截图中的精确阈值未公开，因此第一版参数全部可配置并带策略版本。

## 测试

```powershell
python -m unittest discover -s tests -v
```

测试使用假数据源时会自动禁用海外指数、ETF 和基金持仓等外部补充请求，避免测试消耗行情额度或因限流卡住。
